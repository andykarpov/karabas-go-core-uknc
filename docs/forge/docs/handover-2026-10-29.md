## Hardware issues fixed this evening

1. **Black screen and no OSD:** the initial wrapper reversed GO's burst pins. RP2040 IO0/GPIO14
   is FPGA `MCU_SPI_IO[1]`/M11 (chip select); RP2040 IO1/GPIO2 is FPGA `MCU_SPI_IO[0]`/N9 (ready).
   The ready pull-down held the incorrectly wired select active, suppressing classic SPI frames
   and leaving `host_busy`/machine reset asserted. Build 26102801 corrects it. The new full-wrapper
   `tb_board_link` reproduces the old absent CAPS reply and verifies CAPS, ready, OSD, reset release,
   burst payload and classic-frame recovery with the actual firmware pull states. Included in `quick`.
2. **Empty browser:** extension metadata used `dsk/sav/img`; Karabas's matcher requires the dot.
   Build 26102802 uses `.dsk/.sav/.img`. `test_media.py` now exercises the actual Karabas matcher
   with space-padded metadata for every slot and all supplied filenames (7 DSKs, 2 SAVs, 2 IMGs).
   This changed metadata only; the timing-accepted FPGA binary from 26102801 is reused.
3. **SD failure after browser → USB export:** the card failed initialization with `0x1E,0xFF`
   until the user fully power-cycled it. The firmware's MCU-only reboot did not stop SdFat's active
   dedicated-SPI multi-sector transfer. The core-owned firmware overlay now calls `syncDevice()`
   before USB-export and serial BOOTSEL reboots, and refuses the reboot if stopping fails.
   `test_sd_reboot.py` exercises the actual generated export routine with active transfers,
   failed stops and absent cards. New firmware is flashed/verified and export from the boot menu
   succeeded. **Export after active media browsing/reading still needs a physical retest.**

Other implemented fixes, already documented/tested: GO I2S word-select one bit before MSB and
inverted BCK; SDRAM input registering, phase alignment and 8192-row refresh; delayed floppy
sector readiness; IDE invalid CHS/EOF rejection; exact Kakave timer rate. See `porting.md`.

the identified device and this core's build directory exposed. The ISE image's Python is old:
use `Path.open().read()/write()` rather than `Path.read_bytes()/read_text()` inside it.

flush block buffers and remount read-only for read-back. A normal SCSI eject through a container

Existing one-off scripts under `build/sd-transfer` have strict candidate/backup guards; inspect and
adapt them deliberately rather than rerunning an old version against the current mounted state.
